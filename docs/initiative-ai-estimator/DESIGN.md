# AI Estimate Builder (oe_ai_estimator) - Design Dossier

## Summary

Complete, implementation-ready design for a NEW backend+frontend module - oe_ai_estimator ("AI Estimate Builder", route /ai-estimator) - that realizes the founder's 4-stage vision (Understand Source -> Collect & Group with Quantities -> Precise Rate Matching with full resource breakdowns -> Estimate Assembly + validation + human-confirm). It is deliberately ADDITIONAL to the two existing surfaces: it fuses the strengths of the agentic /ai-agents infra (user-selected provider/model via resolve_provider_key_model + AgentRunner ReAct loop) with the grounded /match-elements retrieval stack (ranker_qdrant.rank, build_search_plan, BGE rerank, apply_to_boq with scaled CWICR resource sub-rows). The key insight, confirmed by reading the code: every primitive already exists and is verified - the ONLY net-new work is the orchestrator that drives an AI agent across ALL source types, lets it reason per-group over real retrieval candidates (re-query / try resources matcher / escalate to LLM rerank / flag for human), and assembles a fully-resourced, validated, human-confirmed estimate. It must NEVER let the LLM invent unit_rates (that is exactly what the legacy quick-estimate does wrong); rates come only from the cost DB. Verified facts: current single alembic head is v3169_field_pwa_sync (authoritative via `alembic heads`); Position.source is a free String(50) so 'ai_precise_estimate' needs no enum migration; rank(req, *, db, ai_settings), AgentService.start_run(*, user_id, agent_name, user_input, project_id, ...), apply_to_boq(db, session_id, spec, applied_by), match_cwicr_items, ElementEnvelope and the session-style router conventions all exist exactly as the dossiers describe. The new module sits in the existing 'Estimating' sidebar group next to /boq, /match-elements, /ai-estimate (not Automation & AI).

2. PIPELINE DESIGN (4 founder stages, each persisted as a run stage with a human-confirm checkpoint)
============================================================
The run is a long-lived job (poll, not stream - call_ai returns full text). Each stage writes its output to the run row + emits an AgentStep timeline. The user-selected AI agent is invoked at stages 1, 2, and per-group inside 3. Stages 3 (apply preview) and 4 (assemble) are deterministic; the AI drives reasoning, never math/money.

--- STAGE 1: SOURCE UNDERSTANDING ---
Input: uploaded file(s) / pasted text / picked BIM model id / selected project documents. Auto-detect format by magic bytes+extension (reuse boq/router smart_import branching).
Process: (a) deterministic extractor dispatch -> normalize to list[ElementEnvelope] via core/match_service/extractors build_envelope(source, raw) for bim/dwg/pdf/photo, and the match_elements/sources adapters (boq_adapter/text_adapter) for Excel/GAEB/free-text. CAD goes through DDC converter when present, degrades to element-summary when absent (boq/cad_import.find_converter early-return). (b) AI classification pass: feed a compact source digest (header table for spreadsheets, summarize_cad_elements() table for CAD, first-N rows / OCR text for PDF) to the user's model via call_ai/start_run and ask it to classify source_type, detected discipline/trades, recommended catalogue+region+construction_stage, recommended group_by keys, and a confidence. ALL user/file text passes ai/prompts.sanitize_user_text + fence_user_content before the LLM.
Output: run.detected_source (type, confidence), run.envelopes (normalized elements), run.suggested_config (catalogue_id, region, group_by[], construction_stage, currency). 
Reused fns: build_envelope, sources/*adapter.iter_elements, boq cad_import + _extract_from_* helpers, summarize_cad_elements, ai_client.call_ai/resolve_provider_key_model, prompts.sanitize_user_text/fence_user_content.
New code: SourceUnderstandingService.detect_and_classify() + a SOURCE_CLASSIFY prompt; envelope coalescing across mixed sources.
Human-confirm checkpoint #1: user reviews/edits detected source type, catalogue/region/currency and group_by before grouping.

--- STAGE 2: DATA COLLECTION & GROUPING (groups with quantities) ---
Input: run.envelopes + confirmed group_by config.
Process: bucket envelopes by signature.derive_group_key(group_by, attrs) into MatchGroup-style rows, SUM canonical quantities per key (area_m2/volume_m3/length_m/count/mass_kg), pick chosen_unit via the existing _pick_unit logic. AI refinement pass (optional, user's model): propose merges/splits of thin or over-broad groups and label each group with a clean human description, seeded against a TAXONOMY of ~15-40 trade buckets derived from CostEstimate TOP-30/40 keyword analysis (earthworks, foundations, structure, masonry, finishing, MEP, ...) cross-checked with CWICR classification.collection/department. The AI suggests; grouping math stays deterministic.
Output: run.groups = [{group_key, signature, element_ids[], quantities{}, chosen_unit, description, status='unmatched'}].
Reused fns: match_elements/service.rebuild_groups + signature.derive_group_key + _pick_unit (lift the grouping core), CostEstimate TOP-N taxonomy as a seed JSON.
New code: a small group-refinement prompt; taxonomy seed file backend/app/modules/ai_estimator/taxonomy.py (from CostEstimate TOP-30/40 + CWICR departments).
Human-confirm checkpoint #2: bulk review groups (Takeoff-style checkbox rows + per-category summary), edit quantities/units, merge/split, exclude groups.

--- STAGE 3: PRECISE RATE MATCHING (the core differentiator) ---
Input: confirmed groups (each -> ElementEnvelope via _envelope_from_group, stamped project_currency/region).
Process PER GROUP, agent-reasoned (this is the net-new value): 
  (1) Build MatchRequest(envelope, project_id, top_k, use_reranker=True) and call ranker_qdrant.rank() -> candidates (already does build_search_plan -> Qdrant search_with_fallback relax-tier ladder -> abstract-parent substitution -> parquet attach -> soft/narrow boosts -> BGE cross-encoder rerank -> optional LLM rerank -> confidence_band_for). 
  (2) The AGENT inspects top candidates' confidence_band + unit compatibility and DECIDES via a ReAct loop with these TOOLS: search_rates(group_desc, unit, region) [wraps rank()], refine_query(new_desc) [re-run rank with a better description], try_resources_matcher [matchers/resources.py for custom single-line], escalate_llm_rerank [reranker_ai.rerank_top_k, cost-gated], get_resource_breakdown(cost_item_id) [read CostItem.components], flag_for_human(reason). The agent may iterate (e.g. low score -> refine description -> re-rank) but can ONLY pick among real returned candidate codes (matchers/llm contract: never fabricate a code/rate).
  (3) Attach the chosen candidate's resource breakdown; compute per-group confidence from retrieval score + hard-filter density + unit match (confidence_band_for already does the band; store the raw float too). Currency HARD filter means a USD project never gets EUR rates (returns none -> honest 'no rate' flag, not a wrong number).
Output: per group {candidate_id, code, unit_rate, currency, score, confidence_band, resources[], status in suggested|tbd|needs_human}. Auto-confirm only when score>=AUTO_CONFIRM (config.py, ~0.88) AND currency/unit match; everything else stays for human.
Reused fns: ranker_qdrant.rank, build_search_plan, qdrant_adapter.search_with_fallback, reranker_bge.rerank, reranker_ai.rerank_top_k, matchers/{vector,resources,llm}, _envelope_from_group, confidence_band_for, cwicr_v3_catalogue.get_catalogue, costs.matcher.match_cwicr_items (fallback when Qdrant absent).
New code: PreciseMatchAgent (register_agent + FunctionTool tools above) OR a non-agentic per-group reasoning loop that calls the same tools (build BOTH so it degrades to deterministic when no AI key); per-group decision/observation logging into AgentStep/run stage state.
AI invocation point: user-selected agent via AgentService.start_run(agent_name=run.agent_name or user's default, project_id=...) OR direct AgentRunner(CallAILLM(provider,api_key,model)) with the module's tool_registry. agent_name comes from a run-create param so the founder's 'agent the user selected' is honored.
Human-confirm checkpoint #3: per-group match review - colored %score badge (green>=0.8/amber>=0.5/gray), expandable resource breakdown, alternative candidates, Apply/override/skip; bulk-confirm; low-confidence rows visually surfaced (never silently dropped).

--- STAGE 4: ESTIMATE ASSEMBLY (positions+resources, totals, validation, confirm) ---
Input: confirmed groups with chosen candidates + resources.
Process: deterministic. Reuse apply_to_boq math: one Position per group (source='ai_precise_estimate', confidence=group float, validation_status='pending', cad_element_ids=element_ids, metadata_={ai_estimator_run_id, group_key, signature, match_method, score, candidates_considered}); explode resources into metadata_['resources'] scaled by factor x qty; unit_rate=sum(res.qty*res.unit_rate) (keep the derived-rate invariant); FX-correct base-currency rollup per line (never blend currencies); apply project markups via boq _calculate_markup_amounts. Then run validation_engine over {positions} with rule_sets=['boq_quality'+regional]; surface the report. Run CHECK_SCOPE (boq/ai_prompts) for completeness_score + missing_items as advisory.
Output: a draft BOQ preview (NOT yet written) + validation traffic-light + completeness score + grand total with per-currency subtotals.
Reused fns: match_elements apply_to_boq (or extract its core into a shared helper both modules call), boq/service recalculate_rates + _calculate_markup_amounts + get_cost_breakdown, validation engine + run_validation, ai_prompts CHECK_SCOPE.
New code: assembly preview builder that returns proposals (kind:'boq_position_proposal', confirmed:False) before the explicit write; the write endpoint POST /runs/{id}/apply creates real BOQ+Positions (verify_project_access guarded), mirroring create_boq_from_estimate.
Human-confirm checkpoint #4: final review of the assembled estimate, then explicit 'Create / append to BOQ'. NEVER auto-write.

## Pitfalls

- ALEMBIC HEAD FORK: current single head is v3169_field_pwa_sync. The new migration v3170_ai_estimator MUST set down_revision='v3169_field_pwa_sync' and be owned by ONE agent; after adding, run `PYTHONPATH=backend DATABASE_URL=postgresql+asyncpg://x:x@localhost:5432/x alembic heads` and confirm exactly one head. Parallel agents have forked heads repeatedly (MEMORY alembic_agent_migration_fork).
- DO NOT let the AI invent unit_rates. The legacy quick_estimate's 'trust the LLM number' is the exact anti-pattern the founder wants fixed. The LLM only understands/groups/quantifies and REASONS over real candidates; every rate+resource breakdown comes from the cost DB (matchers/llm contract: re-order a shortlist, never fabricate a code).
- CURRENCY NEVER-BLEND is load-bearing money correctness: ElementEnvelope.project_currency is a HARD filter (USD project gets zero EUR candidates -> honest 'no rate' rather than a wrong number); apply_to_boq rolls up per-line in base currency via Project.fx_rates. Never sum across currencies in one total; keep per-currency subtotals. Empty currency resolves from region, never default EUR (MEMORY v3_db_eur_defaults_killed).
- Two parallel matcher stacks exist (module-level match_elements/sources + core/match_service ElementEnvelope/extractors/ranker_qdrant). Standardize the new module on ElementEnvelope + ranker_qdrant.rank (the richer v3 path) and clearly map adapters->envelope; do NOT fork the abstraction a third time.
- ifc_class poisoning: never promote a synthetic source label (BoQ/PDF/Text category) into ifc_class - it becomes a Qdrant hard filter that zeros 100% of candidates (MEMORY match_elements_three_filter_bugs). The boq/pdf adapters already guard (keep ifc_class only when it startswith 'Ifc'); preserve that.
- Photo->measured-quantity is a STUB (CV YOLO/PaddleOCR pipeline unbuilt); photo extractor synthesizes from AI estimated_* keys, confidence forced 'low'. Ingest photos for classification/defects but never rely on them for precise measured quantities - surface low confidence, require human confirm.
- Schedules/equipment/resources do NOT carry primary estimable quantities (Activity.resources is loose JSON, boq_position_ids are links). Use them to enrich rates/labor/scope-coverage, not as inputs to the group->quantity step.
- Validation must run with the RIGHT rule sets: always boq_quality (16 universal) + the project's regional standard. A SKIPPED report scores None, NOT 1.0 - don't treat empty validation as pass. New positions start validation_status='pending'; the run must call run_validation and reflect the traffic-light before apply; ERROR-severity rules block the write.
- Agent tool-use is a brittle text protocol (<tool_call>{...}</tool_call> parsed from prose), not native function-calling; small/cheap models may fail to emit the block. Lean on Sonnet/Opus for the reasoning loop AND build the deterministic (no-agent) fallback so the module works with no/cheap AI.
- resolve_provider_and_key (2-tuple) silently falls back to ANY available key/env/config.json; for 'the model the USER selected' fidelity ALWAYS use resolve_provider_key_model (3-tuple) and report the actually-used provider/model on the run. Catch its ValueError (JWT_SECRET rotation makes keys undecryptable) -> 're-enter your key', never a 500.
- Confidence must be a REAL model/retrieval-derived score in [0,1] or None - never fabricate a 0.5 placeholder; both existing services explicitly refuse to. A position with no real confidence stores None.
- Money + quantity fields are stored as STRINGS on Position/CostItem (SQLite-era); coerce to Decimal in service code, never round through float. Takeoff/DWG measurements are Numeric(18,6).
- Qdrant SERVER mode is required to ingest DDC v3 snapshots (embedded QdrantClient(path=) raises NotImplementedError on recover_snapshot); a module assuming embedded vector DB silently gets zero candidates. Encoder (BGE-M3, ~700MB-2GB) loads lazily under a single-flight lock - first match is slow; plan graceful degradation to lexical.
- Worktree isolation spawns stale base refs - first instruction to any build agent: `git checkout <current main HEAD>` + verify alembic heads==1 before writing migrations (MEMORY feedback_worktree_isolation_stale_base, bit the team 5x).
