# OpenConstructionERP - UX Audit (2026-06-06)

Whole-app navigation and clarity audit against the founder yardstick: every meaningful result reachable in 2-3 clicks from the sidebar, every module understandable to any construction professional worldwide on first visit. Covers all 19 sidebar groups (static source-level audits) reconciled against a live browser walk of the 12 flagship routes on v6.10.0.

## 1. Executive summary

The app is mature and broad: 120 modules, every page renders real content with no white screens, no stuck spinners, no raw i18n keys, and money handling is consistently honest (never blends currencies, FX-never-blend, Decimal-string coercion). Most groups already meet the bar. The weaknesses are systemic, not per-page, and three patterns cost the most clicks and clarity.

First, cold-start project context. Project-scoped pages are excellent once a project is active (it persists session-wide, verified live), but nothing auto-selects one on login, so the first gated page in a session costs 3 clicks (sidebar + open switcher + pick) and several pages dead-end on a list detour (/files, /procurement, /validation) instead of an inline picker.

Second, surface duplication with no differentiation. Three AI-estimate surfaces, three Monte Carlo surfaces, Carbon vs Sustainability, Bid Management vs Tendering, QMS vs the Quality group, and two BIM-requirements surfaces all overlap with near-identical labels and no cross-links, so a first-time user cannot tell which to use.

Third, i18n leakage on data values. Page chrome is translated, but raw enum tokens, status filters, region/building-type labels, stage names, and thrown error strings render in English across many pages, undercutting the worldwide-clarity goal. The single worst live finding is /reporting, whose widgets stay as empty grey skeletons even with a project selected, with zero empty-state guidance, so it reads as broken.

## 2. Methodology

Click convention: a sidebar item click is click 1 (expanding a group does not count). Then count real interactions (tab switches, project pickers, dialogs, form opens) until the primary result of the module is on screen. Selecting a project counts as a click; pages that remember the last project score better. The live walk confirmed the active project persists session-wide, so a gated page is 3 clicks the first time in a session and 1 click for every subsequent gated page.

Clarity score 1-5: 5 = instantly clear to a first-time non-English user; 3 = usable but requires guessing; 1 = founder-only knowledge required.

Depth priority: high = needs a real deep-work pass (UX restructure, missing connective tissue, confusing flow); medium = several concrete fixes; low = polish only.

Coverage: 19 static source-level cluster audits (every sidebar group, ~80 routes) plus one live authenticated browser walk of the 12 flagship routes on v6.10.0 (backend healthy, 120 modules), logged in through the real /login demo Admin card. Screenshots for every walked route are saved under qa-tests/_ux-audit/. Where the live walk contradicts a static score, the live walk wins and the conflict is noted.

### Live browser walk reconciliation (v6.10.0)
The live walk overrides the following static scores:
- /reporting: static scored it 3/medium. Live walk shows the widget grid never resolves - perpetual grey skeletons even with a project selected and with zero empty-state guidance. Promoted to clarity 2, depth HIGH. This is the weakest flagship page live.
- /procurement: live first-time cost is 3 clicks (sidebar + open switcher + pick), dropping to 1 thereafter. Static estimate of 2 was optimistic for first-in-session. Its data-less empty state is exemplary and should be the template for /reporting.
- /documents -> /files: live confirms /documents silently redirects to /files (titled "Project Files") while a separate "DOCUMENTS" sidebar group also exists - three names for overlapping concepts. Clarity 3.
- /ai-estimator: live confirms a real backend gap - GET /api/v1/ai-estimator/meta returns 404 (both dash and underscore spellings). Page degrades gracefully but the call is dead.
- Global live findings: demo/seed projects are named with cryptic dev slugs (AIEST-USD-mq1xbrsl) that pollute the dashboard, projects grid and every Switch Project dropdown; the top-bar context line always reads the schedule-specific copy on every module; a mojibake em-dash renders in the /takeoff dropzone helper text.

## 5. Quick wins (cross-cutting, deliverable in bulk)

QW1 - Remember-last-project everywhere. Pages that fall back to projects[0] and silently write it into the global store (/dwg-takeoff ~639, /bim ~1761, /qms ~171, /tasks ~910) or that hold their own local project state (/bim/federations ~868, /carbon, /sustainability ~154, /pipelines ~102, /property-dev ~265) should all read useProjectContextStore as the single source of truth and only commit a project the user explicitly chose. Pattern: `const projectId = routeProjectId ?? ctxProjectId; useEffect(() => { if (chosen) setActiveProject(chosen); }, [chosen])` - never on the projects[0] fallback path.

QW2 - One standard empty-state component. /procurement already ships the exemplar ("No purchase orders... will appear here once created"). Apply the same teaching empty state (icon + one-line purpose + primary CTA) to /reporting widgets, /boq grid when no project, /supplier-catalogs stub tabs, and any page currently showing perpetual skeletons or bare em-dashes. Never render a perpetual grey skeleton or a dead disabled control as the only state.

QW3 - Inline project picker on every "requires project" gate. Replace the "Go to projects" CTA (which dumps users on a list) with an inline picker that calls setActiveProject and renders the result in place. Apply to /files EmptyState (~491-508), /procurement, /documents redirect target, /field-reports RequiresProject, /payroll, /meetings, /correspondence, /contracts (auto-select when projects.length === 1), and the /dashboard QuickUploadCard disabled state.

QW4 - Translate raw enum/status values in filters and badges. A bulk i18n-sweep pass for status filter <option> labels and badges that currently print the raw enum: /subcontractors (~349-354), /variations (~696-700), /service (~501-512), /equipment status+ownership (~373-393), /changeorders (add "executed"), /assets operational_status, plus BI scope/severity/condition, project-controls "record(s)/no data", and the /reports thrown error strings. Pattern: `t('module.status_'+s, {defaultValue: humanize(s)})`.

QW5 - Carry project scope through every cross-module deep link. Many cross-links navigate without the project id and rely on shared state (not new-tab safe): /boq Validation/Finance links (~757-766), /coordination quick-action tiles (~495-538), MoC/Variations linked-record chips, /safety rollup tiles, /ncr bottom links. Pattern: append `?project=${projectId}` (and `?focus=${recordId}` where a specific record exists) and have the target auto-open the match.

QW6 - Disambiguate the three Monte Carlo surfaces and the duplicate pairs. Add a one-line cross-reference in the /5d InfoHint, the /risks Monte Carlo tab and /risk-analysis stating which is canonical and linking the others; similarly cross-link Carbon<->Sustainability, BIM Rules requirements<->/requirements/matrix, and Bid Management<->Tendering. This is cheap connective tissue that resolves most of the IA-overlap confusion until the merges land.

QW7 - Consolidate the triplicated converter-install UX. The CAD/BIM converter install panel is duplicated on /quantities, /bim and /data-explorer. Extract one shared component into a single Settings surface and link to it from all three. Removes maintenance drift and three competing setup walls.

## 6. Systemic recommendations

Information architecture. Resolve the duplicate-surface debt deliberately rather than per-page: the AI-estimate trio, the three Monte Carlo entry points, Carbon/Sustainability, Bid Management/Tendering, QMS vs the Quality group, and the two BIM-requirements surfaces. For each, pick a canonical home, fold or relabel the rest, and add explicit "when to use which" notes. Reconcile the /documents vs /files vs "DOCUMENTS" group naming to one label. Move misfiled routes out of the wrong group (/dashboards Snapshots out of Finance; /portal/payments out of the sidebar entirely). Reconsider advancedOnly on the backbone money pages (/finance, /analytics, /reports) and on /cde, which Transmittals depends on - hiding the backbone in Simple mode breaks the dependent advanced pages.

Connective tissue. The strongest groups (Commercial PipelineBanner, Scheduling PlanningCrossLinks, Quality inspect->defect->close loop) prove the pattern works; extend it to the orphans (/takt, /portfolio/capacity, /portfolio/leveling, /risk-analysis, /tendering) and make every cross-link carry project + record context (QW5). Make read-only rollup tiles and dashboards clickable into their source module (/safety, /project-controls, /analytics, Executive reporting tab). Where a workflow is half-wired (NCR CAPA, Punchlist location, Transmittal recipients, supplier-catalog stubs), either finish it or be honest that it is read-only - never ship a control that silently discards input.

Onboarding and cold-start. The biggest click cost across the whole app is the first project selection in a session. Add a sensible auto-select (most-recently-updated project) or an inline picker on every gated page (QW1 + QW3) so no page ever dead-ends a first-time user on a list. Pair this with the demo-data reseed (item 20) and a module-aware top-bar context line so the very first authenticated screen looks like a real construction portfolio, not debug fixtures. Standardize one DismissibleInfo explainer pattern on the pages still missing it (/payroll, /meetings, /requirements/matrix, /bim/rules, /project-controls, /sustainability) and keep a persistent compact page title independent of the dismissible banner so identity survives dismissal (/takeoff).
